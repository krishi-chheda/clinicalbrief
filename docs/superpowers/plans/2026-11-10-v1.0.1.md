# ClinicalBrief v1.0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.0.1: the patch backlog, a measured accuracy figure for note extraction, a gated semantic-search
experiment, and a de-identified researcher view.

**Architecture:** All work stays inside the existing FastAPI backend (`clinicalbrief-backend`), Next.js 16 frontend
(`clinicalbrief-frontend`) and Supabase Postgres. Schema changes are new numbered migrations the user applies.
Evaluation tooling lives in `clinicalbrief-backend/eval/` and runs in-process through `app.cli`.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy, pytest (SQLite + `TEST_PG=1` pgserver), Next.js 16, Tailwind, Ollama (local).

**Spec:** `docs/superpowers/specs/2026-11-10-v1.0.1-design.md`

## Global Constraints

- Python 3.12 only: `py -3.12`. Backend tests: `py -3.12 -m pytest tests -q` and `TEST_PG=1 py -3.12 -m pytest tests -q`.
- Gate before each reviewer handoff: `.githooks/pre-push` (secrets, PG tests, `npm run typecheck`).
- The assistant never commits; "Commit" steps = hand the user the `git add`/`git commit` lines.
- No scripts that write to the live DB. Migrations are applied by the user in the Supabase SQL editor.
- Patient text only goes to loopback models; on Render model features degrade to a labelled fallback.
- Version string `1.0.1`, displayed `v1.0.1`.
- Wording: the research view is "direct identifiers removed — not a validated de-identification". Accuracy figures always
  carry n, method, 95% CI, and "labels AI-drafted, pending author review" until the author has reviewed them.

## Review Focus

1. A researcher hitting an endpoint not in the original list (record, graph, review queue, search, copilot welcome text) — expect no name/DOB: parametrised test in Task 9 covers every GET that returns patient data.
2. Patient names containing regex metacharacters or short names ("Al", "Lee") — expect whole-word, escaped matching, no mangling of words like "Allergy": test in Task 8.
3. Nonce CSP with Turnstile and GSAP inline styles — expect no CSP violations on `/`, `/login`, `/roadmap`, 404: browser check in Task 6.
4. Eval scorer on a note with zero gold entities or zero predictions — expect P/R defined (reported as n/a), no ZeroDivisionError: test in Task 12.
5. Search comparison run without Ollama embedding model present — expect a clear error naming `ollama pull nomic-embed-text`: Task 14.

### Task 8: D1 — de-identification service

**Files:** Modify `app/services/clinical_privacy.py`; Test `tests/test_deid.py`.

**Produces:**
- `pseudonym(patient_id: str) -> str` → `"Patient " + hmac_sha256(settings.PSEUDONYM_KEY, patient_id).hexdigest()[:6].upper()`; `PSEUDONYM_KEY` from env, default derived from `JWT_SECRET`/`SUPABASE_URL` so it is never a constant in code.
- `deidentify_patient(data: dict) -> dict` → first_name `"Patient"`, last_name = 6-hex code, `date_of_birth` None, `birth_year` int|None added; other keys untouched.
- `redact_for_research(text: str, names: Iterable[str]) -> str` → existing regex redaction + each name (≥2 chars) replaced as an escaped, case-insensitive whole word with `[NAME]`.
- Delete `known_names`.

- [ ] Tests: stable pseudonym per id, different ids differ; `redact_for_research("Mr. Lee has allergy; LEE denies", ["Lee"])` → no "Lee", "allergy" intact; name with `"O'Brien"` / `"(x)"` handled; empty names no-op.
- [ ] Implement; green; commit.
